# Design decisions and known limits

The reasoning behind the main choices in this project, and what the design does not do. The numbers are
in [`RESULTS.md`](RESULTS.md), which is generated from `results/` by `py tools/collect_results.py`.

## Decisions

| # | Decision | Why |
|---|---|---|
| D1 | Memory contents come from a case-statement boot ROM with a UART bootloader. The RAM has no initial contents | No RTL module uses an initial block, and a new program needs no FPGA rebuild. |
| D2 | Machine-mode subset of Zicsr, a machine timer interrupt and precise traps | Illegal instructions, misaligned accesses and access faults all trap, so the cores never fail silently. |
| D3 | Zifencei (FENCE.I) is implemented as a pipeline flush | It lets riscv-tests `fence_i` and arch-test `Fencei` run. |
| D4 | A multi-cycle core instead of a single-cycle one | 7-series block RAM reads are synchronous (UG473). A single-cycle core would need 64 KB of LUT RAM. |
| D5 | 5-stage pipeline with full forwarding, a 1-cycle load-use and CSR-read-use stall, branches resolved in EX (2-cycle penalty) and traps taken in MEM | This is the textbook organisation (Patterson and Hennessy, Harris and Harris). Committing in MEM makes exceptions precise with no extra state. |
| D6 | Misaligned loads, stores and jumps trap (mcause 0, 4 and 6) | The ISA allows it, and it keeps the load/store unit at one access per instruction. `rv32ui-ma_data` therefore reports its documented expected failure. |
| D7 | A fixed 1-cycle bus with strict decoding and word-only I/O | It is the simplest bus a block-RAM SoC needs. Unmapped addresses fault instead of aliasing. |
| D8 | riscv-arch-test is pinned to 2.7.4 | Later versions need the Sail model and Ruby. 2.7.4 ships reference signatures generated by Sail. |
| D9 | Lockstep checking compares the retired-instruction trace with the golden model, and timing-dependent reads take the RTL's value | Ibex and Spike co-simulation use the same method. |
| D10 | Verilator 5 (`--binary --timing`) runs the long tests on the same testbench | Icarus runs this SoC at about 10 k cycles/s and Verilator at about 1 M cycles/s. |
| D11 | Benchmarks are Dhrystone (riscv-tests version, -O3 -fno-inline) and CoreMark (-O2 -funroll-loops) | Related cores publish one or the other. |
| D12 | The toolchain is the xPack riscv-none-elf-gcc 14.2.0-3, with clang as a second compiler for some tests | One pinned compiler makes `sw/prebuilt/` reproducible. |
| D13 | Waveform figures are dumped with Icarus | The regression's Verilator binaries are built without trace support, for speed. |
| D14 | Verilator is used only when make and a C++ compiler exist | Plain Windows has neither, so the long tests run in WSL or Linux. |
| D15 | Ready-made programs in `sw/prebuilt/`, checked against a fresh build by the regression | Running the board does not depend on a compiler install. |
| D16 | `--port auto` in the host tools pings each serial port | Some PCs show the board as two COM ports; the bootloader's answer identifies the UART. |
| D17 | Board results are stored per core (`results/board_<core>_<name>.json`) | Both cores are measured on the board, and one must not overwrite the other. |
| D18 | xsim gets its parameters from a generated wrapper module rather than `xelab -generic_top` | It avoids quoting Verilog literals on the Windows command line. |
| D19 | FPGA part `xc7a50ticsg324-1L` | The Nexys A7-50T carries the industrial low-power XC7A50T. This is the part in Digilent's board files. |
| D20 | On-board self-test (`host/board_hil.py`): random programs and riscv-tests print their state over the UART, and every byte is compared with the golden model | The same programs run on the RTL in the regression first (layer `hil`). Board-mode programs set every register they can read, avoid interrupts, cycle and instret reads and loads from unwritten RAM, so their output does not depend on timing or on the previous program. |
| D21 | Vivado Tcl is checked statically (`tools/check_tcl.py`). Verilator lint and the Yosys latch check report N/A when the tool is missing | No Tcl interpreter is needed outside Vivado. Lint and the latch proof run in the WSL or Linux regression. |
| D22 | Diagrams are drawn by `tools/make_diagrams.py` and refused if they break the drawing rules (`tools/diagram.py`) | Black-and-white orthogonal diagrams, with no crossings and no text touching a line, are checked by a script instead of by eye. |
| D23 | riscv-arch-test's `LA()` macro is built from a copy of `arch_test.h` that writes `auipc` + `addi` instead of the `la` pseudo-instruction (`sim/run_sim.py`, `arch_env()`) | Binutils 2.42 and later reject `la x0, sym`, which `jalr-01` uses once. The replacement is the same 8 bytes, so the Sail reference signatures still apply. The vendored upstream file is unchanged. |
| D24 | The CPU runs at 50 MHz, made from the 100 MHz oscillator by an MMCM | At 100 MHz the design misses timing. At 50 MHz the worst slack is +2.266 ns for the pipeline (Fmax about 56 MHz) and +1.459 ns for the multi-cycle core (about 54 MHz). `clock.cpu_hz` in `params.json` sets the clock, and every derived file follows it. |

## Known limits

- RV32I with Zicsr and Zifencei only: no M extension, no compressed instructions, machine mode only.
- Misaligned accesses trap rather than being split in hardware (D6).
- Programs must fit in the 64 KB of block RAM.
- Branches resolve in EX with no prediction, so every taken branch or jump costs two flushed cycles in the
  pipeline. Earlier branch resolution or a small predictor is the obvious next step.
- Vivado 2018.2 officially supports Windows 10, not Windows 11. The builds here ran on Windows 11 without
  problems.
